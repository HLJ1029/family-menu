# Humi 1.1.79 Login And Share Release Implementation Plan

> **Historical plan — share policy superseded on 2026-09-07:** The 1.1.80 phone acceptance showed that a navigate-only share bridge can leave the user in H5 with “没能打开微信发送页”. The current share contract is `navigateTo → redirectTo`, advances only when the first attempt fails or remains unconfirmed, confirms handoff only from page visibility/page-leave events, reuses the same token, and never uses `reLaunch`. The navigate-only constraints below document the 1.1.79 implementation and are no longer release requirements.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a 1.1.79 mini-program experience build whose H5 login and share actions enter native pages through `navigateTo`, recover visibly on failure, keep native tabs disabled, and are ready for the user’s phone acceptance.

**Architecture:** Keep the production experience as the legacy H5 shell. Import the verified 1.1.78 mini-program archive as the native-page baseline, but force the package-level native-shell candidate flag off. Replace the deferred `postMessage`/multi-method H5 bridges with one explicit `navigateTo` attempt, and make every failed identity or ticket exchange land on a visible retry path.

**Tech Stack:** React 19, Vite 7, WeChat Mini Program JavaScript/WXML, Node.js assertion scripts, Playwright.
