# Humi 游客态登录入口修复设计

## 背景与根因

小程序首次打开时已经提供“微信登录 / 先体验 Humi”二选一。用户选择游客模式后会进入 H5 兼容版；此后打开“我的家”，页面只说明登录后的能力，没有可点击的登录入口。

根因是 `UserCenter` 的游客分支只渲染静态说明，`main.jsx` 传入的 `authProps` 也没有包含登录动作。现有身份回归只覆盖首次启动选择，没有覆盖“先以游客体验、稍后主动登录”。

## 目标

- 在“我的家”的游客卡片中提供明确的黑色主按钮“微信登录”。
- 只在用户点击按钮后调用现有微信小程序登录桥，不自动登录、不静默建号。
- 登录成功后继续复用现有原生身份页、H5 ticket 交换和家庭落点逻辑。
- 登录桥无法打开时，在当前游客卡片内显示可理解、可重试的提示。

## 非目标

- 不改变首次启动的“微信登录 / 先体验 Humi”选择。
- 不改变游客菜单、计划和清单的本机保存方式。
- 不修改账号、家庭、权限、API、数据库或会话格式。
- 不增加全局常驻登录横幅，也不把顶部头像改成直接登录。
- 本次只产出本地候选和验证结果，不部署、不上传、不提审、不发布。

## 交互与组件边界

`GuestFamilyExplanation` 保持当前说明文案，在说明下增加：

1. 黑色主按钮“微信登录”；
2. 仅在发起登录或登录桥失败时显示的状态文案。

按钮通过 `UserCenter` 接收 `authProps.onWechatLogin`，不在展示组件内复制登录逻辑。`main.jsx` 负责提供统一动作：

- 微信小程序 WebView 内：调用现有 `requestWechatLoginFromMiniProgram`；
- 调用已发起：显示“正在打开微信登录…”；
- 原生桥回调失败：恢复为可再次点击状态，并提示退出重进或更新小程序；
- 非微信小程序环境：不伪造可用登录，提示从微信小程序打开 Humi。

登录成功后的 session、身份完善、H5 ticket 和家庭加载全部沿用现有链路。

## 数据流

```text
游客打开“我的家”
  -> 点击“微信登录”
  -> UserCenter 调用 authProps.onWechatLogin
  -> main.jsx 调用现有小程序登录桥
  -> 原生 identity 页面执行 wx.login
  -> 现有 H5 ticket 回到 H5
  -> 现有登录态与家庭加载逻辑接管
```

该流程不会在按钮点击前读取 bootstrap、调用 `wx.login` 或创建账号、家庭。

## 错误处理

- 登录桥未打开：游客卡片保留，按钮仍可再次点击。
- 非小程序环境：显示“请从微信小程序打开 Humi 后登录”。
- 服务端、身份完善或 ticket 错误：继续由现有身份链路处理，不在游客卡片新增第二套错误模型。

## 测试与验收

先增加会失败的回归，再写产品代码：

- 游客以 `?humiGuest=1` 进入后可继续使用核心页面，不自动发起登录；
- 打开“我的家”时可见且只有一个主登录按钮“微信登录”；
- 点击按钮会调用现有小程序身份入口 `/pages/identity/index?action=login`；
- 登录桥失败后按钮恢复可用，并显示失败提示；
- 非小程序环境点击不会伪造成功登录；
- 现有首次启动、身份、H5 入口、产品 smoke、构建和 secret scan 继续通过。
